# 终端与现代工具

交付可在实际 shell 中复现、输入输出有边界、退出与清理可验证的命令或脚本；工具清单是按需候选，不是安装任务。

## 工作流

1. 确认 cwd、目标路径、平台、shell 版本和现有授权。用原生能力或 `Get-Command` 检查当前任务需要的工具及实现身份。
2. Windows 命令、引号、编码或自动化任务先读 [PowerShell 约束](references/powershell.md) 的相关章节。
   选工具、版本或安装渠道时读 [现代 CLI 清单](references/modern-cli-tools.md)。
3. 输入以参数数组、结构化 stdin 或已核验的文件传递；减少 shell 层数，禁止把外部文本重新解释成代码。
4. 有限范围读取与输出，按命令合同判断退出码；可并行的独立只读操作合并执行，依赖步骤、写操作和审批顺序执行。
5. 区分调用等待窗口、子进程超时和总预算；观察已有进程后再重试。后台任务记录 PID、日志与退出清理。
6. 修改后验证实际结果，包括包含空格/非 ASCII 的路径和相关失败分支；报告执行版本、cwd、退出码与未测平台。

## 可复用自动化的合同

- 脚本注明依赖、输入输出、工作目录、允许写入范围、退出码、超时与副作用，提供 `--help` 或 PowerShell 对应帮助入口。
- 无人值守不等待 TTY 选择或凭据输入；可变输入显式传入，不依赖个人 profile 或隐式当前目录。
- 输出优先结构化，诊断与机器输出分流；写入按风险支持预览、幂等或回滚，不能把 dry-run 当作实际执行证据。
- 脚本新增或实质修改后实际运行相关分支；只校验语法时注明未执行行为。一次性排查不自动变为永久脚本。
- 临时文件、清理和外部服务边界见 [安全与交付](../../../doc/ai/security-and-delivery.md)。

工具缺失先回退。需要安装时先把具体包、版本、来源、校验和影响说明清楚，依当前授权执行；不得批量补齐清单。
