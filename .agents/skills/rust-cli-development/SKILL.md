# Rust CLI 开发与迁移

交付与任务一致的 Rust 实现或可审阅设计、兼容行为证据和验证结果。请求仅限设计时保留实施边界。

## 先确认合同

1. 阅读 [Plan.md](../../../Plan.md) 的相关阶段；从 [来源索引](../../../doc/ai/source-index.md) 定位基线。
   先确认 Cargo 工程是否已经建立，避免把初始化时的“尚无工程”当成永久事实。
2. 顺着 CLI 输入、配置合并、执行计划、后端调用和退出状态检查相关源码、调用方与测试。
   涉及外部格式或 API 时核对固定版本文档；缺少运行证据的行为标为未验证。
3. 为本次变更写最小合同：输入、默认值、优先级、输出、失败状态及兼容差异。
   小修复直接配回归场景；跨模块变更将取舍和失败模式写入一份设计，并由计划链接。

现有行为与测试映射以 [迁移合同](../../../doc/migration-contract.md) 为准；先核对历史 Python 与固定后端源码。

新功能、修复、评审和交接按 [工程流程](../../../doc/ai/engineering-workflow.md) 选择适用步骤，
覆盖简单设计、职责/依赖边界、错误处理、兼容、测试、文档和完成检查。
涉及脚本、引用、编码或进程控制时读取 [终端 Skill](../terminal-tooling/SKILL.md) 的对应参考。

## 迁移时需要核对的边界

按任务选取相关行，不要求每次全量检查。这里列的是验收范围，目标行为由合同确定。

| 边界 | 需要覆盖的结果 |
| --- | --- |
| CLI | 短/长选项、重复 scheme/Java 参数、`--` 后透传、帮助/版本独立调用、非法参数 |
| XML | 嵌套 include、相对路径基准、重复与覆盖顺序、空值/未知节点、缺失或损坏文件、循环 include |
| 转换规则 | 全局/局部/尾部选项、默认 scheme、多协议文件与数据源、数据版本覆盖 |
| 输出矩阵 | 多输出、rename、tag/class 筛选、无匹配条目及命令数量 |
| 路径与文本 | work_dir、Unicode、空格/引号、Windows 盘符/UNC、换行和后端编码 |
| Java 执行 | 显式路径、JAVA_HOME 与 PATH 的选择、启动失败、stdin 批次与 EOF |
| 并发与退出 | 合法并发上限、无重复无遗漏、失败汇总、非零退出、大输出、取消和子进程回收 |
| 预览 | `--test` 生成可检查的计划，不启动后端、不写导出文件 |

## 实现与验证

- 先用纯函数或可注入边界分离解析、规划与执行；只按实际复杂度引入 crate、线程池或异步运行时。
  错误保留输入位置和原因，CLI 在边界统一输出与映射退出码。
- Java 启动用 `std::process::Command` 的参数与工作目录接口，不经 shell 执行。
  启动参数和发往 xresloader `--stdin` 的命令文本是两种协议，分别测试转义、分隔和编码。
  固定后端的 stdin 分词不支持 shell 反斜杠转义；无法表示的值在启动前报错，原始 XML option 片段保持原合同。
- XML 和输入路径不授予执行命令、任意网络访问或扩大文件范围的权限。
  工作目录尽量绑定子进程，避免并发任务修改整个进程的当前目录。
- 读取 stdout/stderr 时防止管道阻塞；完成、失败和取消路径均需等待或回收本次拥有的子进程。
  同一目标的超时重试先确认状态，发布与文件覆盖不能盲目重放。
- 输入/规划用确定性单元测试；CLI 与进程生命周期用仓内 fake-java 和 fixture 集成测试。
  每个测试有独立临时目录；使用可观测结果断言，不复制实现。回归测试尽量先重现原症状。
- 从根规则中的 Cargo 门禁选择对应范围。首次建工程需确定 edition、最低支持版本并生成锁文件；后续常规检查使用 `--locked`。
  Cargo.toml 依赖使用显式 `^` 兼容范围，Cargo.lock 保证可复现；升级核对官方稳定版本与 MSRV。
  feature 组合和跨平台测试按合同选择，不假定所有 feature 能同时启用。
- Python 兼容测试通过 `XRESCONV_CLI_BIN` 使用本地编译二进制，下载逻辑离线测试；测试替身不进入正式程序。
  自动测试不查询、下载或执行外部 xresloader Release/JAR/sample；后端升级不应使本仓库门禁随之变化。
  Python 自动下载的平台映射应与当前发布矩阵一致，不承诺未构建架构的预编译包。
- 记录目录、命令、环境、退出码、测试数量和结果；`--no-run` 只说明编译，不能记为测试通过。
  集成依赖缺失时仍完成独立验证，明确剩余阻塞；必要检查通过后停止无依据的重复运行。

## 发布准备与交接

涉及临时产物、凭据、依赖供应链、CI、迁移或发布时先读 [安全与交付](../../../doc/ai/security-and-delivery.md)。
仅在任务涉及发布时核对目标平台、制品标识、JDK/后端依赖、干净目录冒烟和回滚制品。
本地/mock、固定后端集成与生产验收分别记录。根据当前授权处理实际发布，不自动提交或上传制品。
收尾同步受影响的使用说明、样本、测试、设计和计划；把已复现的问题沉淀为测试，流程经验才进入本 Skill。
